# Rise LVL UP - Browser Must-Have Audit (2026-02-22)

## Выжимка
- Браузерный контур стабильный: `npm run e2e` -> `6/6 PASS`.
- Регрессии зелёные: `npm run test:run` -> `47/47 PASS`, `npm run build` -> `PASS`.
- Главные продуктовые риски до итерации:
  - когнитивная перегрузка (слишком много карточек одновременно),
  - недоиспользованный recovery-механизм (слабый anti-relapse loop),
  - риск неаккуратного старта local-first UI до полной загрузки состояния.

## Как проводился аудит
- Browser-first проверка через Playwright (критичные пользовательские сценарии).
- Внешние субагенты в параллель:
  - Product Management,
  - UX Research/UX Writing,
  - Behavioral Science,
  - QA/Reliability.
- Синтез только high-impact изменений (без косметики).

## Топ-приоритеты (Must-Have)
1. Снизить «dashboard anxiety» через явные рабочие режимы экрана.
2. Усилить recovery-loop после срыва (чтобы провал не ломал мотивацию).
3. Защитить local-first запуск от состояния «UI рендерится раньше гидратации».
4. Поддерживать e2e-стабильность при изменениях информационной архитектуры.

## Что внедрено в этой итерации
1. Рабочие экраны в `AppShell`:
   - `Фокус`, `Планирование`, `Ревью`, `Все`.
   - Дефолт: `Фокус` (снижение когнитивной нагрузки в момент входа).
2. Recovery XP-буст в RPG-правилах:
   - после `habit_relapse` активируются recovery-заряды,
   - первые позитивные действия получают усиленный XP,
   - буст постепенно расходуется.
3. Безопасный bootstrap в `App`:
   - полный UI показывается после завершения `loadInitial`.
4. Адаптация e2e к новым рабочим экранам:
   - сценарии явно переключают режим экрана, где это нужно.
5. Persistent Storage protection flow:
   - добавлена диагностика persistent storage и кнопка `Защитить данные`.
6. First-run onboarding:
   - добавлена карточка `Быстрый старт (1 минута)` с фиксацией завершения в local storage.

## Практики аналогичных продуктов (что взять, что избегать)
- Todoist: быстрый capture + минимальный шум в главном экране.
- Sunsama: ритуал фокуса на «сегодня» вместо бесконечного списка.
- TickTick: сильная связка задач и времени (таймер как часть потока).
- Habitica/Streaks: поддержка возврата после срыва важнее наказания.
- Антипаттерн: геймифицировать штрафами без «моста возврата» в действие.

## Что осталось (не блокирует текущий релиз)
- PWA/mobile-first упаковка.
- Защита local data на уровне persistent storage API + UX-поток запроса.
- Лёгкий first-run onboarding (3 шага).
