# Rise LVL UP Design (2026-02-21)

## Section 1: System Architecture (Approved)

MVP строится как локальное веб-приложение без авторизации и облачной синхронизации. Это осознанный выбор под персональное использование: меньше инфраструктуры, меньше точек отказа, быстрее итерации. Стек: `React + TypeScript + Vite`, состояние в `Zustand`, хранение в `IndexedDB` через `Dexie` (устойчиво к перезагрузке вкладки и не ограничено только одной сессией, как обычный in-memory store). Интерфейс один экран и полностью на русском.

Информационная архитектура экрана:
- верх: фокус-таймер (`30/5` по умолчанию, полная ручная настройка)
- центр: чек-лист задач и идей + быстрые блоки планирования `Сегодня` и `Неделя`
- низ: RPG-прогресс, привычки, блок шумов (white/pink/brown/silence)

Чтобы не повторить ошибки прошлых прототипов, поведение отделено от UI. Все ключевые действия оформляются как доменные события (`task_done`, `focus_completed`, `habit_done`, `habit_relapse`, `task_missed`). Эти события обрабатывает единый слой правил прогресса, который централизованно считает XP, уровень, штрафы, ограничения и recovery-механики. За счет этого интерфейс только отображает состояние и отправляет события, а не содержит бизнес-логику.

Доменные модули:
- `TimerEngine`: циклы фокус/перерыв, ручные пресеты
- `TaskEngine`: CRUD задач/идей и статус выполнения
- `HabitEngine`: daily-статусы привычек `done/skipped/relapse`
- `RPGEngine`: XP, уровни, стрики, пенальти-ограничения
- `AudioEngine`: генерация/воспроизведение шумов и громкость

## Section 2: Data Model and Progress Rules (Pending Validation)

Базовые сущности MVP:
- `Task`: `id`, `title`, `type(task|idea)`, `status(todo|done|missed)`, `planScope(inbox|day|week)`, `goalId?`, `createdAt`, `completedAt?`
- `FocusSession`: `id`, `focusMinutes`, `breakMinutes`, `startedAt`, `endedAt?`, `status(running|done|aborted)`
- `Habit`: `id`, `title`, `mode(build|quit)`, `createdAt`, `active`
- `HabitLog`: `id`, `habitId`, `date(YYYY-MM-DD)`, `status(done|skipped|relapse)`, `note?`
- `Goal`: `id`, `title`, `scope(week|custom)`, `targetCount`, `currentCount`, `status(active|done|archived)`, `deadline?`
- `DayPlan`: `date`, `priorityTaskIds[]` (до 3 задач)
- `WeekPlan`: `weekStartDate`, `priorityTaskIds[]` (до 10 задач), `goalIds[]`
- `RPGProfile`: `level`, `xpTotal`, `xpInLevel`, `lastLevelDownAt?`, `streakDays`
- `RecoveryQuest`: `id`, `sourceEvent`, `title`, `xpBonusMultiplier`, `expiresAt`, `status(active|done|expired)`
- `AudioSettings`: `noiseType(off|white|pink|brown)`, `volume(0..1)`, `enabledPerSession`

Событийная модель начисления:
- `task_done` -> `+25 XP`
- `day_priority_done` -> `+10 XP` (дополнительно, если задача была в плане дня)
- `goal_step_done` -> `+15 XP` (дополнительно при продвижении по цели)
- `focus_completed` -> `+1 XP за минуту фокуса` (минимум 10 минут)
- `habit_done` -> `+35 XP`
- `habit_skipped` -> `-8 XP`
- `habit_relapse` -> `-20 XP` + проверка level-down
- `task_missed` -> `-10 XP`

Ограничения честности (anti-exploit):
- максимум `1000 XP` за 24 часа
- лимит “быстрых кликов”: не более 5 закрытий задач за 60 секунд
- за 24 часа уровень может снизиться максимум на 1
- не более 3 приоритетов в плане дня (фокус на главное)

Level curve (простая и понятная для MVP):
- XP до следующего уровня: `need(level) = 120 + 40 * (level - 1)`
- при штрафах сначала снимаем `xpInLevel`; если ушли в минус, возможен level-down с учетом ограничения `1/24h`
- после relapse или level-down создается `RecoveryQuest` с множителем награды `x1.5` на ближайшие 3 целевых действия

Принцип UX минимализма:
- один экран без сложной навигации
- быстрые действия в 1-2 тапа
- приоритет: ясность, а не количество виджетов

## Section 3: Data Flow, Error Handling, and Reliability (Pending Validation)

Поток данных строится по схеме `UI -> Domain Event -> ProgressRules -> Store -> UI`. Любое действие пользователя (отметить задачу, завершить фокус-сессию, отметить привычку, перенести задачу в план дня/недели) сначала превращается в доменное событие. Дальше событие обрабатывается в одном месте: валидируется, получает расчет XP/штрафа, обновляет связанные сущности (например, `Task`, `Goal`, `RPGProfile`) и только после этого пишет новое состояние в хранилище. Это убирает рассинхрон между блоками и не допускает “магии” внутри компонентов.

Надежность и отказоустойчивость для MVP:
- все операции локальные и быстрые; оптимистичное обновление UI допустимо только после успешной валидации события
- транзакционное сохранение через IndexedDB: если обновление упало, состояние откатывается и показывается понятная ошибка на русском
- восстановление после перезагрузки: активная фокус-сессия поднимается из состояния (с корректировкой прошедшего времени)
- защита от дубликатов событий: `eventId` + окно дедупликации, чтобы двойной клик не начислил двойной XP

Обработка ошибок минималистично, но строго:
- ошибки валидации (например, пустой title, выход за лимит приоритетов дня) показываются коротким текстом рядом с действием
- ошибки хранилища показываются в верхнем системном баннере с кнопкой “Повторить”
- аудио-шум при ошибке воспроизведения автоматически уходит в `off`, приложение продолжает работать без блокировки
- критические ошибки логируются во внутренний `debug log` (локально), но не засоряют основной интерфейс

Итог: в любом сбое пользователь не теряет контроль, а приложение остается понятным и рабочим.

## Section 4: Testing Strategy and MVP Boundaries (Pending Validation)

Тестирование MVP строим в 3 слоя, чтобы быстро ловить ошибки логики и не сломать минималистичный UX.  
Слой 1: unit-тесты на чистую логику (`ProgressRules`, кривая уровней, штрафы, анти-эксплойт лимиты, recovery-квесты, дедупликация событий). Здесь критично зафиксировать предсказуемое поведение на одинаковом входе.  
Слой 2: store/domain-тесты (операции с задачами, планом дня/недели, целями, привычками, восстановление активной сессии после reload).  
Слой 3: e2e на ключевые пользовательские сценарии в браузере: добавить задачу, запустить/завершить таймер, закрыть приоритет дня, отметить привычку, получить/потерять XP, включить/выключить шум, восстановиться после срыва.

Минимальный “Definition of Done” для релиза MVP:
- все unit и e2e тесты зеленые
- интерфейс полностью на русском
- приложение работает офлайн после первого открытия
- перезагрузка страницы не ломает текущий прогресс
- штрафы и recovery строго следуют выбранным правилам

Четкие границы MVP (чтобы не раздувать объем):
- включено: локальные данные, день/неделя/цели, таймер, привычки, RPG, шумы
- не включено: аккаунты/логины/облако, голосовой AI, сложная аналитика, социальные функции
- не включено: медицинские рекомендации; режим “избавления от плохих привычек” остается поведенческим трекером и системой самоконтроля

Риск-контроль на MVP:
- если аудио нестабильно, шумы остаются опциональным модулем и не блокируют ядро
- если рост сложности интерфейса превышает лимит, приоритет всегда у главного одностраничного потока
- если правила прогресса окажутся слишком “мягкими/жесткими”, корректируем числа XP без изменения структуры движка
